## 1. 测试配置

| 项目 | 值 |
| --- | --- |
| 服务器 | 8核，23 GiB可用内存，50 GiB挂载盘 |
| API限制 | 1.5 CPU，3 GiB |
| Worker限制 | 1 CPU，2 GiB |
| PostgreSQL限制 | 0.75 CPU，2 GiB |
| Redis限制 | 0.25 CPU，1 GiB，maxmemory 768 MiB |
| Kafka限制 | 0.75 CPU，2 GiB |
| 用户数 | 12,000 |
| 作者数 | 500 |
| 视频数 | 50,000 |
| 有效关注关系 | 375,978 |
| 普通作者 | 作者3，5,419名粉丝 |
| 大V作者 | 作者2，11,999名粉丝 |
| 每轮事件 | 100条：普通作者80条，大V作者20条 |
| Fanout轮数 | 全写扩散3轮，推拉结合3轮 |
| Feed压测 | 20 VU，60秒，page size=20 |
| Feed请求分布 | 80%首屏，20%游标页 |
| Feed轮数 | 全写扩散3轮，推拉结合3轮 |

全写扩散组保留作者2的11,999条真实粉丝关系，将隔离数据库中的路由粉丝数设为9,999。推拉结合组
将路由粉丝数恢复为11,999。每组开始前清空独立benchmark Redis。

事件由测试工具直接写入Kafka，不经过视频发布HTTP接口。多模态Provider和外部模型调用关闭。
