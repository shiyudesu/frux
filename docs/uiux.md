# Frux - UI/UX 规格（完整功能版）

> 版本：1.0  
> 日期：2026-07-24
> 产品定位：电脑 Web 端短视频 Feed + 完整运营后台  
> 关联文档：`README.md`、`docs/product.md`、`docs/architecture.md`、`docs/engineering.md`、`docs/modules/*.md`

## 0. 快速摘要

- 产品一句话：Frux 是面向电脑刷短视频用户的 Web Feed 产品，提供 16:9 桌面沉浸浏览、发布、互动、关系、消息、审核、运营、推荐治理、播放优化、监控告警和系统治理能力。
- 前端目标：实现设计文档中的完整功能页面与完整交互状态，覆盖 `docs/product.md` 和 `docs/modules/*.md` 的全部 P0/P1 能力。
- 核心用户：在电脑浏览器里刷抖音/TikTok 式短视频的用户，以及负责审核、运营、监控和治理的后台人员。
- 主设备：电脑 Web，默认 1440px 到 1920px 宽屏，核心舞台按 16:9 设计；手机网页提供窄屏自适应体验。
- 风格关键词：抖音/TikTok 式沉浸、Apple 高级质感、黑白强对比、毛玻璃、精细动效、信息清晰。
- 技术落地：前端先实现完整页面、状态和交互；数据层使用统一适配层，真实接口接入时替换 mock 数据源。

## 0.1 使用方式

- 这份文档是 UI 的唯一真相，颜色、字号、间距、组件、页面结构都以这里为准。
- 新增页面、组件或交互时，先更新本文件对应章节，再进入实现。
- token（设计变量：全站统一的颜色、字号、间距等）来自第 4 节。
- variant（同一组件的不同样式：比如主按钮、危险按钮）来自第 5 节。
- 前端交付以完整体验为准：页面、导航、空状态、加载、错误、成功反馈、权限状态、响应式全部具备。

## 1. 产品范围

### 1.1 完整前端范围

- 账户：注册、登录、退出、当前用户资料、资料编辑、角色状态。
- 关系：关注、取关、关注列表、粉丝列表、作者关系状态。
- 视频：Web 发布视频、视频详情、我的作品、作品状态、删除视频。
- Feed：16:9 桌面刷视频、上下切换、游标分页、刷新、曝光/观看/完播上报。
- 互动：点赞、取消点赞、收藏、取消收藏、两级评论、热门/最新、回复分页、评论点赞、发表和权限删除。
- 个人内容库：喜欢、收藏、观看历史、稍后再看；仅喜欢可按隐私设置公开。
- 创作者管理：公开/私密作品查询、关键词与日期筛选、批量公开/私密/删除、公开/私密合集及成员管理。
- 消息：消息列表、未读计数、批量已读、评论/回复/评论获赞结构化深链和 legacy 消息兼容。
- 推荐：多源候选召回、上下文排序、稳定分页、曝光去重、反馈抑制、规则配置、效果指标展示。
- 审核：Agent 初审、人审任务、审核详情、通过、驳回、违规下架、审核日志。
- 后台运营：视频查询、审核任务查询、任务分配、运营配置管理、操作日志。
- 播放优化：播放参数、预加载建议、首帧、卡顿、播放质量视图。
- 系统治理：限流检查、降级开关、死信任务重试、治理日志。
- 监控告警：指标看板、告警规则、告警事件、触发中与恢复状态。

### 1.2 产品形态

- 用户 Web 端：面向电脑刷短视频用户，提供沉浸 Feed、发布、互动、关系、消息和个人中心。
- 运营 Web 端：面向运营、审核、管理员，提供审核、内容、推荐、播放、监控、告警、治理、配置。
- 同一个 Web 应用通过角色与导航切换用户端和运营端。

### 1.3 设计原则

1. 电脑刷视频优先：主舞台按 16:9 宽屏设计，鼠标滚轮、方向键、J/K 键都能切视频。
2. 内容第一眼可见：视频、标题、作者、互动数据在首屏形成完整判断。
3. 抖音/TikTok 习惯：关注/推荐频道、快速切换、点赞动效、评论侧栏、作者关注入口保持短视频产品直觉。
4. 桌面短视频质感：近黑背景、紧凑导航、沉浸舞台、克制圆角、玫红主操作和青色品牌点缀。
5. 完整状态：每个页面具备加载、空状态、错误、成功、权限受限、提交中。
6. 后台高效率：运营后台以表格、筛选、抽屉详情、批量操作和状态标签为核心。

## 2. 信息架构与导航

### 2.1 用户 Web 端导航

- 顶部栏：56px 高，包含全局搜索、投稿、消息、登录/头像和退出入口。
- 左侧栏：宽屏 160px、紧凑桌面 72px，包含四类 Feed、消息、投稿和个人资料；Frux 标识固定在栏顶。
- Feed 主体：左侧导航 + 沉浸视频舞台；评论关闭时舞台占满内容区，打开后增加 346px 评论与详情区并缩小舞台。
- 快捷操作：滚轮切换、方向键切换、J/K 切换、L 点赞、F 收藏、C 评论、Space 播放/暂停。

### 2.2 运营 Web 端导航

- 顶部栏：页面标题、全局搜索、环境标识、角色、用户菜单。
- 侧边栏：审核工作台、内容管理、推荐治理、播放优化、指标监控、告警规则、告警事件、系统治理、配置管理、操作日志。
- 详情形态：表格行点击打开右侧抽屉；复杂操作进入详情页；危险动作进入确认弹窗。

## 3. 核心流程

### 3.1 电脑刷 Feed

1. 用户进入 `/feed`，默认频道为推荐。
2. 页面拉取 Feed 数据，16:9 舞台展示当前视频。
3. 竖屏视频在 16:9 舞台内居中播放，左右用封面模糊背景和暗色渐变补齐。
4. 页面按当前频道已经返回的顺序准备上一条、当前条和有界后续视频；准备完成的媒体在切换时直接复用。
5. 用户滚轮下滑、方向键下、J 键进入下一条；滚轮上滑、方向键上、K 键回上一条。
6. 视频曝光、观看、完播事件自动上报。
7. 用户点赞、收藏、评论、关注作者，UI 即时更新并保留失败回滚能力。
8. 用户在操作栏“更多”中选择“不感兴趣”时，已登录且当前推荐请求有 request ID 才展示可提交项；
   提交中防重复，成功立即从当前有序列表移除，失败保留视频并显示错误。若成功响应晚于推荐刷新，只要仍在推荐频道，
   视频/作者抑制仍应用到新一代列表；仅在离开推荐频道或会话重置时清除。该操作不伪造已完成反馈。
9. 评论关闭时视频获得最大空间；打开评论后宽屏右侧出现 346px 面板并缩小舞台，窄屏继续使用电脑版右侧抽屉，不提供移动端底部面板。

### 3.2 发布到审核

1. 用户进入发布页，拖拽视频或点击上传。
2. 选择本地视频后立即显示带 controls 的本地播放器，不等待校验和或上传会话。
3. 选择封面后同时作为本地视频 poster，并显示独立封面缩略图。
4. 页面编辑标题、简介和可见范围；更换文件或离开页面时释放旧 object URL。
5. 本地解码失败只提示预览限制，不清空选择或自动开始上传。
6. 点击发布，进入上传中与提交中状态。
7. 成功后作品进入“审核中”，用户在我的作品查看。
8. Agent 初审和人工复审结果通过状态标签、消息通知、作品详情展示。

### 3.3 互动与消息

1. 用户点赞/收藏视频，或在公开讨论中切换热门/最新、展开回复、回复根/回复、点赞评论和执行允许的删除。
2. 评论面板保留每视频草稿、排序、已加载页面和展开状态；失败操作显示局部错误，评论点赞乐观更新失败时回滚。
3. 根评论、回复和首次评论点赞通过耐久 Outbox 生成 `COMMENT`、`COMMENT_REPLY`、`COMMENT_LIKE` 消息，并抑制自通知。
4. 激活可操作评论消息时先标已读，再进入 typed 视频讨论路由，展开根并高亮目标；目标不可用时显示安全反馈。
5. legacy 或缺少结构化目标的消息仍可阅读和标已读，不从正文猜测跳转。

### 3.4 个人内容中心

1. 用户进入 `/profile`，先加载聚合资料和当前 Tab，其他 Tab 按需加载。
2. 资料头图展示 112px 圆形头像、昵称、账号、性别、简介、关注、粉丝、公开作品和获赞统计。
3. 一级 Tab 固定为作品、喜欢、收藏、观看历史、稍后再看；推荐内容只在推荐 Feed 展示，作品二级视图为公开作品、私密作品、合集。
4. 公开/私密作品支持关键词、生命周期和创建日期筛选、稳定游标加载和选择模式；卡片真实展示处理中、审核中、未通过、已发布和已下架；批量公开、私密、删除使用确认和忙碌状态。
5. 合集支持创建、编辑公开/私密状态、软删除，以及在编辑器内独立搜索、继续加载自己的公开/私密非删除作品并增删成员。
6. 喜欢、收藏、观看历史和稍后再看卡片点击后打开全屏连续播放层，从所选项开始支持上下切换、临近分页、评论、互动和连续播放；关闭后回到原 Tab、滚动位置和卡片焦点。
7. 观看历史显示最近进度或“已看完”，支持移除单项和清空；Feed/内容库播放“更多”可加入稍后再看，稍后再看列表和播放层支持移除。
8. 公开主页只显示公开作品、公开合集和隐私允许的喜欢，不显示编辑、批量、收藏、历史、稍后再看或私密内容。
9. “短剧”和“我的预约（Appointments）”没有数据能力，所有主页均不渲染这两个 Tab 或占位入口。

### 3.5 审核与内容治理

1. 运营进入审核工作台，按状态、风险分、时间、审核员筛选。
2. 点击任务进入详情抽屉或详情页。
3. 查看 9:16 视频预览、Agent 风险分、作者信息、历史日志。
4. 选择通过或驳回，填写原因或选择原因模板。
5. 对已上线违规内容执行下架，写入操作日志。

### 3.6 推荐、播放、监控、治理

1. 运营查看推荐治理页，调整召回、排序、打散、曝光去重配置。
2. 播放优化页展示首帧、卡顿、预加载、缓冲阈值。
3. 指标监控页展示 Feed 成功率、互动成功率、审核待处理、首帧 P95、告警中数量。
4. 告警规则页创建或启停规则，告警事件页查看触发与恢复。
5. 系统治理页调整降级开关，重试死信任务，查看治理日志。

## 4. 设计系统（Tokens：设计变量）

### 4.1 风格方向

- 用户 Web：`#161823` 近黑背景、紧凑桌面导航、圆角沉浸视频舞台、强对比文字、右侧互动栏和按需展开的评论面板。

- 表格文字：13/20，表头字重 700。

### 4.5 16:9 Feed 舞台规则

- 宽屏舞台占满导航和顶部栏之外的可用高度，使用 16px 圆角；打开详情面板时宽度自适应收缩。
- 竖屏短视频使用 `object-fit: contain` 居中显示。
- 背景层使用当前视频封面，`scale(1.08)`、`blur(30px)`、透明度约 52%。
- 舞台左右使用暗色渐变承接背景，保证文字与按钮可读。
- 右侧互动栏贴近视频右缘；评论打开后在宽屏使用 346px 推挤式面板。
- 底部控制栏显示真实播放/暂停、时间、进度、自动/手动画质、0.5x-2x 速度、连续播放、静音和全屏状态，不显示静态伪进度。
- loading、buffering、DASH fallback、可恢复重试和终止错误使用 `role=status` 文案，不只依赖动画或颜色。
- 桌面滚轮一次切一条视频，动画时长 360ms。
- 1280px 以下统一使用 72px 图标导航和覆盖式详情抽屉；更窄窗口仍保持电脑版 16:9 舞台，不切换移动导航或评论底部面板。

## 6. 页面规格

### 6.1 登录/注册

- 结构：暗色短视频预览背景、居中浅色认证面板、账号、密码、昵称、登录、注册。
- 约束：只展示后端已支持的账号密码能力，不伪造二维码、手机号或第三方登录。
- 状态：输入校验、提交中、登录成功、账号冲突、密码错误、权限状态。
- 跳转：普通用户进入 Feed；运营角色进入审核工作台。

### 6.2 Feed 浏览

- 结构：56px 顶部导航、160px/72px 左侧栏、沉浸 FeedStage、互动栏、底部播放器控制、按需展开的详情评论区。
- 主操作：切换下一条视频。
- 必备能力：关注/推荐频道、搜索入口、播放/暂停、滚轮切换、键盘切换、点赞、收藏、完整两级评论、分享、关注作者、曝光上报、观看上报、完播上报。
- 宽屏布局：160px 左侧栏 + 舞台；评论打开后增加 346px 推挤式面板。
- 紧凑桌面布局：72px 图标栏 + 舞台 + 按需覆盖式详情抽屉。
- 窄屏布局：保持紧凑电脑版侧栏、16:9 舞台和右侧评论抽屉，不提供独立手机布局。
- 评论状态：加载/空/错误、根加载更多、回复加载更多、创建/点赞/删除独立 busy/error、作者墓碑、讨论不可用和 focused 高亮。
- 状态：首屏骨架、视频加载、准备就绪、预加载失败后可见播放器重试、播放错误、Feed 空状态、接口错误、操作成功、操作回滚。
- 播放控件：播放器外壳和按钮均由应用自定义，底层 video 不显示浏览器 controls、媒体右键菜单、画中画或远程播放入口；质量与速度使用原生可聚焦 select，连播按钮公开 pressed 状态，buffering/error 状态不抢焦点。

### 6.3 视频讨论

- typed 路由：`/videos/${number}`；可选 search 为 `comment=<rootId>&highlight=<targetId>`，`highlight` 不能脱离 `comment`。
- 结构：可读视频舞台、共享 `VideoDetails`、共享 `ThreadedComments`；当前详情舞台不展示 Feed 的视频点赞/收藏/关注操作栏，也不渲染相关推荐。
- 直接访问或 reload 时重新读取视频和 thread context；根自动展开，目标滚动到视口中央并高亮约 3.2 秒。
- 缺失或非法 focus 参数仍展示可读视频及普通讨论，并提示参数无效；删除/治理/私密目标显示“讨论不可用”，不泄露隐藏内容。
- 状态：视频加载、视频不可用、评论加载/空/错误、目标高亮和讨论不可用。

### 6.4 发布视频

- 结构：上传区、视频预览、封面、标题、简介、可见范围、发布按钮。
- 能力：拖拽上传、封面选择、标题校验、上传进度、提交审核；成功文案明确“等待审核”后跳转我的作品。
- 状态：空上传、上传中、上传失败、提交中、审核中。

### 6.5 个人内容中心

- 结构：无圆角外层卡片的全宽资料头图、112px 头像、内联统计、一级 Tab、作品二级 Tab、筛选工具栏、3:4 密集视频网格和合集网格。
- 本人一级 Tab：作品、喜欢、收藏、观看历史、稍后再看。
- 作品二级视图：公开作品（按 `visibility=public`，包含待审/拒绝并显示状态）、私密作品、合集。
- 能力：一次原子保存头像/昵称/简介/性别和喜欢列表隐私；收藏固定显示“仅自己可见”，不提供公开控制；打开关注/粉丝弹窗；关键词与日期筛选；游标加载；批量公开、私密、删除；合集 CRUD，合集编辑器独立搜索/分页候选作品；历史单项删除/清空；稍后再看移除。
- 推荐内容只在推荐 Feed 展示，不进入个人主页 Tab。
- 卡片：六列可容纳的 3:4 封面、点赞数叠层、单行标题；管理视图可显示生命周期/可见性标签，历史卡显示秒数或已看完。
- 本人点击待审、处理中、拒绝、私密或下架作品时打开受保护 WorkViewer；加载短期 media/cover access，ready baseline 直接播放，只有封面或浏览器无法播放原始源时显示真实状态和重试。公开主页不请求 owner access。
- 响应式：≥1280px 配合 160px 侧栏并允许六列网格；更窄窗口统一保留 72px 紧凑桌面侧栏和桌面内容结构，不切换手机单列布局。
- 状态：每个 Tab 独立维护 loading、error、empty、ready、loadingMore；关注/粉丝弹窗按打开代次和活动 Tab 接收分页，切换或关闭后旧页不得追加；清空历史先失效在途历史页且清空期间不启动新页；公开主页按 `userId` 重置全部用户态并忽略旧请求；并发乐观移除失败时只恢复对应项目；批量和编辑操作有 mutating/busy 状态。

### 6.6 消息中心

- 结构：未读计数、刷新、全部已读、游标消息列表和加载更多；当前实现没有消息类型筛选 Tab。
- 能力：区分视频获赞、新评论、新回复、评论获赞、关注和系统消息；结构化评论消息进入目标视频讨论。
- 激活顺序：先标已读；只有 `video_id/root_comment_id/comment_id` 都合法时导航。
- 兼容：无目标 legacy 消息保持只读激活和已读能力；未知类型使用安全图标/标题 fallback。
- 状态：空消息、加载/加载更多、局部已读、全部已读、导航目标不可用。

### 6.7 公开主页

- 结构：复用本人主页的全宽资料头图、一级 Tab 和 3:4 网格，不显示本人管理控件。
- Tab：作品、合集；只有 `liked_videos_public=true` 时增加喜欢。
- 能力：通过单目标鉴权关系接口读取关注/已关注状态，不扫描关注列表；打开公开视频、浏览公开合集；本人访问自己的公开页时可返回个人主页。
- 隐私：不显示私密作品、私密合集、收藏、观看历史、稍后再看、批量管理或资料编辑。
- 状态：资料、作品、喜欢、合集分别提供加载、错误、空和加载更多状态；关注状态旧读取不能覆盖后续成功关注/取关。

### 6.8 关系页

- 结构：关注列表、粉丝列表、搜索作者、关系状态。
- 能力：关注、取关、查看作者、进入作者作品。
- 状态：空关注、空粉丝、操作成功。

### 6.9 搜索结果

- 结构：共享顶部搜索框、视频/用户 Tab、视频网格、用户列表和独立分页按钮。
- 能力：URL 编码关键词、视频/用户独立稳定分页、进入视频讨论页或公开主页、浏览器前进/后退同步输入框。
- 状态：输入提示、搜索中、加载更多、空结果、局部搜索错误和重试；切换 query 后旧响应不得覆盖新结果。

### 6.10 审核工作台

- typed 路由：`/admin/reviews`；通过现有 History router 进入懒加载 Admin Shell。
- 结构：权限过滤侧栏、优先级筛选、稳定游标任务表格、刷新和加载更多。
- 能力：通过“待我处理 / 我正在审核 / 最近完成”查看审核任务；Reviewer 与 Operator 只看到各自服务端确认权限范围。
- 状态：权限验证、登录、服务端 403、首屏加载、独立刷新、独立加载更多、空任务、错误和重试；403 会清空缓存任务并隐藏表格。

### 6.11 审核详情

- typed 路由：`/admin/reviews/${number}`；非正整数和非法标识进入安全 not-found，不发起无效 API。
- 结构：9:16 受保护预览、标题、作者、机器证据、自动决定、审核记录、审核占用状态和判定区。
- 能力：开始审核、刷新恢复、自动/手动延长审核时间、放回待处理、通过、驳回；opaque lease token 只保留在页面内存，刷新通过 resume 轮换；同一 case/version 与判定 payload 的失败重试复用幂等键。
- 预览：视频播放器下方单独提供“视频封面”检查区；封面缺失显示独立不可用状态，不影响视频证据和判定操作。
- 状态：加载、预览不可用、开始/恢复/延长/放回/提交 busy、成功终态、审核占用过期、case/video 版本冲突和服务端 403。占用过期保留证据、禁用旧动作并返回任务列表。
- 文案：用户界面不使用“案件、审核主体、不可变历史、领取案件、租约、续租”；对应显示为“审核任务、视频内容、审核记录、开始审核、审核占用、延长审核时间”。

- 能力：筛选提交后固定 applied filters 与 cursor；默认创建终点保留秒并覆盖当前分钟；下架/恢复必须选择注册原因、可选 1000 字备注、确认并携带当前 version。
- 状态：加载、空、错误、加载更多、服务端 403、版本/状态冲突、提交中和审计确认后的成功。筛选草稿变化不能与旧 cursor 混用。

- 状态：指标加载、空指标、保存成功。

- 状态：图表骨架、空数据、刷新成功。

- 状态：空日志、加载、查询错误。

## 7. 文案规范

- 整体语气：短、轻、直接。
- Feed 操作文案：关注、已关注、点赞、收藏、评论、分享、下一条。
- 发布文案：发布视频、上传中、上传成功，等待审核；媒体未完成时显示“处理中并等待审核”。
- 审核文案：通过、驳回、下架、填写原因、审核结果已提交。
- 监控文案：刷新数据、创建规则、告警中、已恢复。
- 错误模板：`加载失败，请重试`、`保存失败，请检查输入`、`当前账号需要运营权限`。

## 8. 可访问性与快捷键

- 所有按钮、输入框、Tab、表格行操作支持键盘聚焦。
- 个人主页一级和二级 Tab 使用 `tablist/tab/tabpanel` 语义，支持左右、Home、End 键切换。
- 资料和合集编辑弹窗使用 `role=dialog`、焦点陷阱、Escape 关闭和关闭后焦点恢复。
- Feed 快捷键：`J` 下一条、`K` 上一条、`L` 点赞、`F` 收藏、`C` 聚焦评论、`Space` 播放/暂停。

- 消息深链和 thread context 加载后滚动目标并短暂高亮；高亮结束不移动键盘焦点。
- 焦点样式使用 Frux 青色外环。
- Feed 舞台文字有遮罩，评论区和表格满足清晰对比。
- 点击热区：Feed 图标按钮 52px，后台行操作 32px 以上。
- 紧凑桌面评论抽屉内排序、回复展开、分页和 Composer 均可纵向到达。
- 个人主页交互控件保持至少 40px 触摸目标，并尊重 `prefers-reduced-motion`。
