## Why

GCFeed 当前个人主页只有资料、关系和作品列表，视觉结构与抖音网页版个人主页差距明显，也缺少用户管理自己发布、喜欢、收藏和观看内容的完整入口。需要将个人主页升级为统一的个人内容中心，并补齐前后端真实数据能力，避免只渲染不可用的仿制标签。

## What Changes

- 将登录用户个人主页重构为与抖音网页版一致的全宽资料头图、两级内容导航、筛选工具、密集作品网格、空状态和资料编辑弹窗，同时继续使用 GCFeed 自有品牌、图标和文案。
- 将公开主页的资料头图和作品网格同步到同一视觉与组件体系，但不暴露私密内容或本人管理操作。
- 扩展个人资料响应，提供性别和获赞总数；账号字段继续作为 GCFeed 的公开账号标识。
- 为当前用户提供游标分页的已发布作品、私密作品、喜欢、收藏、观看历史和稍后再看列表。
- 为作者作品列表增加关键词、日期范围和可见性筛选，并支持幂等的批量公开、设为私密和删除操作。
- 增加创作者作品合集及合集成员管理，个人主页可浏览和维护自己的合集，公开主页只展示公开合集。
- 持久化观看历史与稍后再看状态；观看上报更新最近观看时间和播放进度。
- 增加个人内容隐私设置；只有喜欢列表可选择公开，收藏始终仅本人可见。
- 不展示抖音个人页中的“短剧”和“我的预约”标签；GCFeed 当前没有相应业务领域，本变更不引入虚假的空功能。
- 保留现有登录、头像上传、资料编辑、关系列表、公开视频查看和作品播放行为。

## Capabilities

### New Capabilities

- `profile-dashboard`: 聚合当前用户与公开用户的资料、关系统计、获赞统计、隐私状态和个人主页标签导航，并定义对应 Web 展示行为。
- `personal-video-library`: 提供喜欢、收藏、观看历史和稍后再看的持久化、游标分页、状态变更与隐私约束。
- `creator-content-management`: 提供公开/私密作品、关键词和日期筛选、批量操作、创作者合集及合集成员管理。

### Modified Capabilities

- `douyin-style-web-experience`: 将个人主页从保留旧接口的样式改造升级为具备真实后端能力的抖音式个人内容中心，并明确短剧和预约不在展示范围。

## Impact

- 后端将扩展账户、视频、互动和 Feed 观看链路，并新增个人内容库/合集相关的 Domain、Application、Persistence 和 HTTP 组件。
- PostgreSQL 将增加作品可见性、用户观看历史、稍后再看、内容合集、合集成员和隐私设置相关字段或表；迁移需保持现有公开视频和互动数据兼容。
- API 将新增个人内容列表、稍后再看、隐私设置、合集和批量作品操作接口，并扩展个人资料与作品查询响应。
- Web 将增加严格类型化的个人主页 API、hooks、标签状态、筛选和分页逻辑，重构 `ProfilePage`、`PublicProfilePage`、`VideoGrid` 及资料编辑弹窗。
- 文档需同步 `docs/product.md`、`docs/architecture.md`、`docs/uiux.md`、`docs/engineering.md` 相关接口说明，以及账户、视频、互动和新增模块文档。
- 验证范围包括 Go 单元/API 流程测试、前端构建、OpenSpec 严格校验及桌面宽屏/紧凑桌面的浏览器视觉与交互检查。
